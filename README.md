# Joya Star Films PM App

Repository baseline for the Joya Star Films Project Management App.

The application is a Next.js App Router project. Product features, database schema/RLS, authentication, provider activation, deployment, and legal content are delivered through accepted implementation work; they are not represented as complete by this baseline.

## Local setup

1. Copy `.env.example` to `.env.local`.
2. Add only the local development values you are authorized to use. Never commit `.env.local` or real credentials.
3. Install the exact lockfile dependency tree:

   ```bash
   npm ci --include=dev
   ```

   `--include=dev` is required when the shell exports `NODE_ENV=production`; formatters, linters, tests, and TypeScript are development dependencies.

4. Start the application:

   ```bash
   npm run dev
   ```

## Quality checks

```bash
npm run format:check
npm run lint
npm run typecheck
npm run build
npm run test
npm run test:coverage
npm run audit:prod
npm run verify
```

`npm run verify` is the baseline quality command. It runs formatting, linting, type checking, production build, tests, coverage, and a production dependency audit.

The pre-foundation repository deliberately contains no behavior tests. The test commands use Vitest's `--passWithNoTests` option only so the baseline remains verifiable without a fake test; real implementation work must introduce test-first behavioral contracts.

`npm run deps:unused` runs Knip as a separate inventory command. It currently reports dependencies reserved for planned implementation and the pre-E2 generated Supabase type artifact; it is not a merge gate at this stage.

## Repository boundaries

- Hermes agents read `AGENTS.md`; Antigravity reads `GEMINI.md`.
- Supabase migrations under `supabase/migrations/` are the only versioned schema source. The tracked `src/lib/database.types.ts` file is generated through the architect-owned schema workflow and must not be manually edited or regenerated by implementation agents.
- Real secrets belong only in local or hosted environment configuration. `.env.example` contains variable names and placeholders only.
- The task brief, accepted implementation specification, and repository instructions define the permitted scope for each change.
